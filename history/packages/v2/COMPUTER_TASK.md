# Единое задание Computer — CAD Agent Team v2

Ты — технический исполнитель архитектуры, созданной ChatGPT. Не перепроектируй роли, workflow или ограничения по собственной инициативе. Это **обновление существующих** четырёх агентов, а не создание новых.

## А. Прочитать пакет и сделать резервную копию

1. Распаковать архив в workspace `computer-admin`; прочитать все документы, prompts, helper и тесты.
2. Проверить существующую установку LibreChat, endpoint `ez-ai`, MCP `freecad`, four agent records; не обновлять сервисы.
3. Через обычный пользовательский Agents API (не Management API/OIDC, не прямую MongoDB) прочитать полные records/expanded representation, найденные по ID и имени.
4. Backup исходной конфигурации 4 агентов в существующий backup каталог LibreChat, с timestamp и контрольной суммой. Проверить возможность отката. Не включать секреты или JWT в backup.
5. Если обнаружен дубликат имени или несовпадающий ID без однозначного сопоставления — остановиться с конкретной проблемой. Не создавать новых агентов.

## Б. Настроить четыре агента

1. Полные тексты `agents/*.md` записать в `instructions` соответствующих existing agents. Не сокращать.
2. Все четыре агента получают `freecad` MCP tools `execute_python_mcp_freecad`, `get_output_page_mcp_freecad`. `execute_python_file_mcp_freecad` не нужен на первом этапе, но не объявлять его отсутствие границей безопасности.
3. Coordinator сохраняет native Subagents card, enabled, `allowSelf=false`, `shareFiles=true`, список IDs Analyst, Builder, Reviewer. Проверить и конфигурацию subagents, и наличие реального нативного инструмента в tools.
4. Не добавлять новые агентов, Agent Chains и другие MCP.
5. Проверить live model catalog и actual model/tool-calling; модели по MODEL_POLICY.md. Не менять EZ AI credentials и глобальные endpoint reasoning.
6. Использовать точечный PATCH обычного Agents API. После каждого PATCH прочитать объект повторно. При ошибке откатить изменённые записи из backup.

## В. Развёртывание ревизий

1. Убедиться, что `/projects` — постоянное примонтированное хранилище FreeCAD; не писать данные только во временную FS контейнера.
2. Сохранить версию `versioning/cad_revision.py` в `<CAD_AGENT_HOME>/bin/` (или стабильный существующий путь с тем же назначением). Избегать замены существующего файла без backup. Не менять настройки FreeCAD, GUI, MCP и Docker.
3. Создать постоянный проектный root `<CAD_WORKSPACE>/<project-slug>/` для **тестового проекта**, не создавать автоматом новую копию реальной сборки.
4. Запустить `versioning/test_revision.py` локально через штатный Python без FreeCAD и проверить результат.
5. Отдельно проверить helper на новом простом тестовом документе FreeCAD (не текущем пользовательском). Создание **отдельного тестового документа в тестовом project_root** для приёмки этой настройки уже входит в разрешённую задачу. Не спрашивай отдельного согласия на scratch-тест; техническое окно Bridge Ask, пока он включён, всё равно требует ручного Run. Создать before → изменение → after; проверить ревизии и неизменный `doc.FileName`.
6. Не переключать Bridge в `Unrestricted` самому. Если пользователь хочет убрать каждое Allow, подготовить короткую инструкцию **однократного** переключения в GUI FreeCAD после успешной проверки версий. Не подменять согласие автоматическим изменением GUI Preferences.
7. Проверь актуальную версию файла `project_state.json` и возможность корректно писать/читать через helper.

## Г. Проверка поведения команды

1. Coordinator должен выполнить простую правку без обязательного Analyst (на тестовом документе).
2. Analyst должен уметь напрямую исследовать FreeCAD; Builder должен уметь сам подготовить и применить изменение тестового документа, сохранив before и after; Reviewer — самостоятельно запросить метрики через FreeCAD.
3. Не запускать write concurrently, не параллелить чтение Reviewer с изменением Builder.
4. Убедиться, что делегация Coordinator → Builder/Analyst/Reviewer происходит по необходимости, а не принудительно всегда.
5. Проверить, что старые исходные файлы и FreeCAD GUI-профиль не затронуты.

## Д. Что не делать

Не менять CREDS_KEY/IV, EZ AI API key, контейнеры, сеть, TLS, MCP Bearer, Docker Compose, MongoDB напрямую, FreeCAD Preferences и исходные CAD-модели. Не включать автозапуск Bridge без отдельного запроса. Не перезаписывать STEP.

## Е. Финальный отчёт

Один отчёт с: backup path, четыре IDs, models/tool calling, tools, subagents, версионирование (helper path, проектная папка, before/after revs, результат проверки), какая реальная модель была затронута (ожидается: никакая), статус режима Ask/Unrestricted, результаты тестов, что осталось сделать пользователю. Секреты не выводить.

**Готово только когда**: промпты применены, инструменты/делегирование подтверждены, helper и журналы проверены на тестовом документе, стратегия без повторного Analyst работает. Полный режим без Allow нельзя считать достигнутым, если Bridge остался в Ask.
