# Версионирование CAD — обязательная часть автономности

## Цель

Не просить разрешения на каждую обычную правку, сохраняя возможность вернуться к **любому завершённому шагу**. Без успешно созданной предшествующей ревизии нельзя начинать изменяющую операцию над ценным документом.

## Реализация

Использовать native `Document.saveCopy()` — сохраняет FCStd-копию **без переключения пути рабочего документа**. Избегать `saveAs()` для snapshot, потому что он меняет активный путь документа.

В пакете есть helper `versioning/cad_revision.py`, который:
- создаёт уникальный `revisions/<UTC>-<random>-before.FCStd` или `...-after.FCStd`;
- проверяет наличие, размер и ZIP-целостность FCStd;
- ведёт `revision_log.json` (фаза, метка, документ, путь, время, sha256, число объектов, fingerprint);
- позволяет прочитать последнюю ревизию и проверить текущую сессию;
- не удаляет старые ревизии;
- не меняет рабочий путь FreeCAD и не закрывает документы.

`project_state.json` содержит инженерный контекст и обновляется Coordinator через `update_project_state()` отдельно. Любое значение этого файла — документированное решение/факт, а не замена текущей геометрии.

## Для каждой изменяющей задачи

1. Перед началом проверяется правильный `App.ActiveDocument` и принадлежность проекту.
2. **BEFORE:** `checkpoint(doc, project_root, 'before', '...')`. Если snapshot не удался — не изменять модель.
3. Изменяющие команды, затем нужный `recompute()`.
4. Read-only проверка фактического результата (геометрия, размеры, ошибки).
5. **AFTER:** `checkpoint(doc, project_root, 'after', '...')`. Если провалился — работа ещё не считается зафиксированной; остановиться, не начинать следующую изменяющую задачу.
6. Обновить проектный state и сообщить итог Coordinator.

Промежуточные исходники STEP/STP никогда не перезаписывать; работать с FCStd-моделью. Если исходный документ открыт из STEP, сначала сохранить его FCStd baseline в каталоге проекта.

Snapshot не является гарантией корректности модели — это страховка от потери предыдущего состояния. Отдельно нужна геометрическая проверка.

## Место хранения

Предпочитаемое хранилище: `<CAD_WORKSPACE>/<project-slug>/`. Для каждой работы `project_root` определяется один раз по существующей структуре `/projects` и остаётся постоянным.

Computer должен проверить реальное Docker-монтирование `/projects` и права; если путь иной, адаптировать **путь**, но не алгоритм. Не сохранять версии во временном каталоге контейнера.

## Проверка на тестовом документе

Перед включением автономных изменений:

- скопировать `cad_revision.py` в постоянный каталог, доступный процессу FreeCAD;
- запустить автономный тест `test_revision.py` (без FreeCAD);
- на **новом тестовом документе**, не пользовательской модели, создать before, изменить параметр, создать after;
- проверить, что два FCStd открываются и имеют разные значения параметра;
- убедиться, что `doc.FileName` рабочего документа не изменился;
- проверить, что `revision_log.json` обновляется.

Создание и изменение только **изолированного тестового документа** разрешено в рамках приёмки пакета. Но если Bridge остаётся в Ask, соответствующие Python-вызовы потребуют штатного Run/Allow. Не переключать режим автоматически.

## Снимки не равны undo

FreeCAD MCP Bridge делает один Undo шаг для `execute_python`, но Undo не гарантирует возврат после закрытия/сохранения документа. Ревизии на диске — отдельная страховка.

## Пределы гарантии

Это решение зависит от того, что агент вызывает checkpoint перед каждым изменением; сам Bridge не перехватывает все операции и не навязывает snapshot технически. Поэтому нельзя объявлять «автоматические ревизии гарантированы», пока не проведены интеграционные тесты. Для жёсткой гарантии потребуется будущий контролируемый MCP-wrapper/operation gateway; он **не входит** в этот пакет.

Если пользователь изменил документ вручную, а простая сверка не заметила — снова собрать фактический snapshot; не считать `project_state.json` абсолютной истиной.
