# CAD Team v2 — непрерывная инженерная работа

## Принцип: проект, а не конвейер

Не каждая пользовательская фраза запускает Analyst → Builder → Reviewer. Выбор следующего действия зависит от **обновлённого состояния проекта и сложности изменения**.

### Роли

| Агент | Роль | Прямой MCP |
|---|---|---|
| CAD Coordinator | Ведёт контекст, уточняет цель, распределяет сложные задачи, может сам выполнять простые правки | `execute_python`, `get_output_page` |
| CAD Analyst | Сам исследует живую модель/сборку, делает измерения, собирает факты | `execute_python`, `get_output_page` |
| CAD Builder | Сам проектирует, изменяет и проверяет в FreeCAD; обязательно делает ревизии | `execute_python`, `get_output_page` |
| CAD Reviewer | Самостоятельно получает актуальные метрики и проверяет геометрию; код в read-only режиме по роли | `execute_python`, `get_output_page` |

`execute_python_file` не требуется ни одному агенту для MVP: все операции возможны через `execute_python`. Это **не** read-only защита: все получатели `execute_python` технически имеют полные права Python.

## Как решать, кого вызывать

- **Небольшая понятная правка**: Coordinator сам выполняет её, если хватает контекста; делегирование необязательно.
- **Сложное параметрическое моделирование/код**: Coordinator даёт Builder чёткую ограниченную задачу; Builder сам читает и изменяет модель.
- **Новый/непонятный документ, неожиданная геометрия или конфликт состояния**: Coordinator вызывает Analyst.
- **Существенное изменение, критичные интерфейсы, коллизии, неопределённость, неудачный тест**: Coordinator вызывает Reviewer.
- **Многошаговая разработка**: аналитик и ревьюер вызываются по событиям, а не на каждом ходе.

### Не вызывать Analyst повторно, если

- продолжается тот же проект и документ;
- известны необходимые параметры, модель и место изменения;
- состояние проекта не изменилось неожиданным образом;
- с предыдущего шага были только собственные зафиксированные изменения агентов.

Небольшая read-only проверка текущего документа допустима, но это **не полноценный повторный анализ**. Субагенты LibreChat запускаются в отдельных контекстах, поэтому каждой новой делегации передаётся компактный контекст проекта из `project_state.json`, а не ожидание «он всё помнит».

## Контекст проекта

Каждый проект ведёт:

- `project_state.json`: текущее имя документа, последняя подтверждённая ревизия, необходимые параметры, подтверждённые факты, решения, ограничения, гипотезы, текущая задача, следующий шаг и открытые вопросы;
- `revision_log.json`: список снимков FreeCAD с точными путями и фазами `before/after`;
- `revisions/*.FCStd`: сохранённые рабочие копии документа.

Coordinator отвечает за обновление `project_state.json` после логического шага, Builder — за запись фактических ревизий. Источник истины о геометрии — **живой документ и проверенные FCStd-снимки**, а не рассказ агента.

Лёгкая проверка соответствия имени документа/количества объектов/fingerprint — сигнал, а не доказательство неизменности. При сомнении выполнить новый осмотр. Нельзя гарантировать обнаружение любого ручного изменения только по такой проверке.

## Единственная живая FreeCAD-сессия

У всех агентов общий FreeCAD MCP server. Запросы к **одной живой модели** должны быть последовательны, особенно изменения.

- Не запускать параллельных mutating tool calls, даже если LibreChat позволяет параллельные subagents.
- Не выполнять read-only ревью параллельно с изменением документа.
- Coordinator разрешает следующую изменяющую работу только после завершения предыдущей.
- Builder внутри одной делегированной задачи может выполнять много последовательных read/write операций; Coordinator не должен нажимать виртуальную кнопку «выполни следующий шаг» на каждой операции.
- После завершения Builder возвращает ID ревизий, проверенные метрики, ошибки и решение, нужен ли Reviewer.

## Политика подтверждений

Пользователь разрешает нормальные согласованные изменения в рамках своей задачи без отдельного подтверждения каждой строки кода. Вместо этого обязательно сохраняются ревизии. Исключения — удаление/перезапись исходников, изменение вне проекта, переустановка сервисов, неопределённые пользовательские требования, операции с чужими файлами, опасные последствия вне CAD.

Факт: Bridge `Ask` всё равно покажет диалог перед **каждым** вызовом Python. Для автономной работы необходим сознательный переход в `Unrestricted` через штатное подтверждение FreeCAD. Этот пакет не переводит Bridge автоматически.

## Правило отчетности

Не рассказывай пользователю о рутинном MCP-вызове или каждом ревизионном файле. По итогам законченного шага: что изменилось, результат измерения, успешность проверки, номер ревизии, оставшиеся проблемы. По простым правкам — короткий ответ.
